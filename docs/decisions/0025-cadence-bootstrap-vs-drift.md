# 0025: 項目に cadence を持たせ、設置して終わるものと劣化するものを分ける (既定の報告は変えない)

- **状態**: 採用 (2026-09-17)

- **文脈**: 標準の 50 項目は性質が 2 つに割れている。**一度設置すれば終わるもの** (LICENSE が在る・squash merge の設定・dependabot.yml の有無) は、誰かが意図的に変えない限り崩れない。**作業そのものが状態を崩していくもの** (ブランチが溜まる・決定が積み上がるのに ADR が書かれない・allow が溜まる・worktree が残る) は、一度直しても次の週には戻っている。

  この 2 つが同じ 1 枚のリストに並んでいるため、監査のレポートで「見るべきもの」と「もう済んだもの」が混ざる。再監査に意味があるのは後者だけなのに、毎回 50 件が同じ扱いで流れる。

  **コスト削減にはならない**ことは先に書いておく。LLM 判定 8 項目は**すべて drift 側**なので、サブエージェントの本数 (11〜17 本) は分けても変わらない。残り 42 件の機械判定は安い。効果はレポートの可読性と、担当の分離である。

- **決定**:
  1. 項目に `cadence: "bootstrap" | "drift"` を持たせ、全項目に必須とする。新しい項目を足す人にどちらかを考えさせるため、省略可にはしない
  2. 分類は **bootstrap 37 / drift 13**。drift は llm 8 件すべてに加え、`no-stale-branches` / `no-committed-secrets` / `claude-settings-local-not-committed` / `claude-worktrees-clean` / `gh-linear-history` の 5 件
  3. `rs-audit-repo.sh` / `rs-audit-github.sh` / `rs-audit-min.sh` に `--cadence <bootstrap|drift>` を足す。**既定は全件のまま変えない** — リポジトリを初めて見るときに設置漏れ (public リポに LICENSE が無い等) が隠れては困る。絞るのは「定期的に見直す」用途のためのオプトイン
  4. `repo-bootstrap` は bootstrap 側を担当する。生成すべきものが `cadence: bootstrap` として機械的に引ける

- **影響**: 定期実行の監査を `--cadence drift` で回せるようになる。機械判定 42 件を毎回流さずに済むが、**サブエージェント数は変わらない**ので費用の桁は動かない。

  既定の挙動が変わらないため、既存の findings・スキル手順・テストへの影響は無い (フィルタは `--cadence` を渡したときだけ効く)。

  分類そのものは判断であって計測ではない。「作業のたびに崩れるか」で切っているが、境目にあるもの (`gitignore-covers-env` は .gitignore を誰かが編集すれば崩れる) は bootstrap に寄せた — 自然に崩れるのでなく、人が変えたときだけ崩れるものは設置側と見なす。
