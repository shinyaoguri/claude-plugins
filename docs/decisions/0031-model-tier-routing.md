# 0031: セッションのモデルの格は機械的に判定し、引き受けるタスクと判断の出口を格で変える

- **状態**: 採用 (2026-10-18, Issue [#207](https://github.com/shinyaoguri/claude-plugins/issues/207))

- **文脈**: セッションを動かすモデルは Fable / Opus / Sonnet / Haiku のどれかで、任せてよい判断の深さが違う。ところが規約 (CLAUDE.md / AGENTS.md) もこのプラグインのフックも、**モデルを区別しない**。軽いモデルに投げても、設計判断や公開 API の意味の選択を自分で下したまま実装が進みうる。しかも [0017](0017-approval-at-the-plan.md) の改訂で入れた `plan-pass` は、トリアージ済みの Issue に紐づくプランを格に関係なく自動承認する。そのため、人がプランを見る機会もない。

  トリアージが固めるのは「何をすれば済むか」(完了条件) であって、「どう作るか」の判断までは固めていない。後者を任せられるかは、モデルの格で変わる。

  本体の契約 (Claude Code v2.1.267 の公式 hooks ドキュメント):

  - SessionStart の入力には `model` がある。ただし `/clear` 後や会話の復旧時には省かれうる
  - PostModelSwitch の入力には `from_model` / `to_model` がある。途中の `/model` はこれで追える
  - PreToolUse / PermissionRequest の入力にはモデルの情報が無い。`$CLAUDE_MODEL` のような環境変数も無い

- **決定**:

  1. **格は自己申告ではなく機械で決める。** 軽いモデルほど、自分に何が分からないかに気付きにくい。だから「難しいと思ったら止まれ」と文書で頼む仕組みは、いちばん止まってほしい場面で止まらない。`hooks/scripts/model-tier.sh` が SessionStart と PostModelSwitch でモデル ID から格を決め、セッション単位の印 (`~/.claude/model-tier/<session>.tier`) を置く。

     | モデル ID に含む語 | 格 |
     |---|---|
     | `haiku` | 低 |
     | `sonnet` | 中 |
     | `opus` / `fable` | 高 |
     | それ以外・欠落 | 判定しない (印を消す) |

     判定できないものを低に倒さない。本体が `model` を省く場面で上位モデルの自動承認まで止めてしまうと、反射で押す OK ボタンが戻ってくるためである。止めそこねても、失うのは人がプランを見る機会だけになる。

  2. **中・低の格には、身の丈と出口を最初に伝える。** SessionStart の `additionalContext` で次の 3 つを注入する。
     - 引き受けてよいもの: 中は「トリアージ済みで直し方が 1 通りに決まる Bug・Task・Docs」、低は「機械的な作業」
     - 自分で決めないもの: Design、意図に依存する選択、公開 API の意味・互換性・原則、完了条件そのもの、複数リポに跨る変更、リポジトリの規約が人の判断を求めるもの
     - 当たったときの出口 (次項)

  3. **判断に当たったときの出口は 2 つに限る。**
     - 判断だけを切り出せるなら、Agent ツールに `model: "opus"` を渡して選択肢・推奨・根拠を返させる。結論を Issue に記録してから続ける
     - 切り出せない、あるいは委ねても決まらないなら、**限界報告** (確かめたこと / 決められなかった点と理由 / 誰が何を決めれば進めるか) を Issue に残し、着手印を外して終える

     黙って自分で決めることだけを塞ぐ。どちらの出口も記録が残るので、後から上位のモデルか人が拾える。

  4. **強制は既存の 2 か所の「通す側」を絞るだけにし、deny は足さない。**
     - `plan-pass.sh`: 格が低なら一切自動承認しない。中なら Issue Type が `Design` のものを自動承認しない。どちらも素通しになり、人がプランを見る
     - `next-task` スキル: 格に合わない候補を選定で落とす

     編集を deny するゲートは置かない。格だけを根拠に止めると、格に合うタスクまで差し戻すことになる。それに、止める根拠が「この格では決めてはならない判断」なら、それを見られる最初の点はプランだからである。

- **退けた案**:
  - **CLAUDE.md への文書ルールだけ**: 判断の要否を判定するのが、判定してほしくないそのモデル自身になる (決定 1 の理由)
  - **Edit / Write を deny するゲート**: 決定 4 の理由。plan-gate がすでに「プランなしの拡大」を止めており、格による絞り込みはプランの承認点に載せれば足りる
  - **リポジトリごとに難易度ラベルを新設する**: 判断が要るかどうかの属性は、Issue Type (`Design`) とトリアージ印として既にある。mokume などは AGENTS.md で「人が先に判断する」対象を定めている。新しいラベルは付け忘れという別の失敗を増やす

- **影響**:
  - 格の印は Claude Code のセッションでだけ置かれる。Codex など別のエージェントには効かない (その環境の hooks で同じ判定を持つかは別途)
  - **既知の限界**:
    - サブエージェントの格は見ない。上位のモデルが `model: "sonnet"` のサブエージェントへ委ねる場合、何を委ねるかは呼ぶ側の責任になる
    - PostModelSwitch では印を書き換えるだけで、文脈は注入しない (出力の契約を確かめていないため)。途中で格が下がると、指示は届かないまま plan-pass の絞り込みだけが効く
  - 逃げ道は `RS_MODEL_TIER=0` (判定ごと止める)。`RS_MODEL_TIER=high|mid|low` で格を固定できる
  - テストは `scripts/test-rs-model-tier.sh` と `scripts/test-rs-plan-pass.sh` の「モデルの格」節が持つ
